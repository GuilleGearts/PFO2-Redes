Preguntas teóricas obligatorias de la consigna del PFO 2.

Pregunta 1

¿Por qué hashear contraseñas?

Almacenar contraseñas en texto plano es una de las fallas más graves de seguridad. Si la base de datos es vulnerada por inyección SQL o filtración de respaldos, las credenciales reales de todos los usuarios quedarían expuestas.

  • Unidireccionalidad: Una función hash criptográfica permite calcular $H = \text{hash}(P)$ en instantes, pero es matemáticamente imposible revertirla para recuperar la contraseña original $P$.
  • Autenticación ciega: El servidor valida el acceso recalculando el hash del texto ingresado y comparándolo con el almacenado, sin necesidad de conocer jamás la clave real.
  • Uso de Sal (Salt): Invalida ataques por tablas arcoíris (*Rainbow Tables*), asegurando que dos usuarios con la misma clave tengan hashes completamente disímiles.
  • Key Stretching: Algoritmos como PBKDF2/scrypt aplican miles de iteraciones para hacer inviable la fuerza bruta.
Pregunta 2

Ventajas de usar SQLite en este proyecto

Para una arquitectura de microservicios o desarrollo formativo, SQLite presenta ventajas directas frente a motores cliente-servidor como MySQL o PostgreSQL:

  • Arquitectura Embebida (Serverless): Corre en el mismo espacio de memoria de Python. No requiere procesos daemon de fondo ni configuración de puertos de red.
  • Cero Configuración: Todo reside en un único archivo autónomo (tareas.db). Clonar y ejecutar es 100% portable.
  • Persistencia Real vs Memoria RAM: A diferencia de estructuras volátiles en memoria, los datos sobreviven a reinicios del servidor.
  • Cumplimiento ACID: Garantiza consistencia en escrituras concurrentes y recuperación automática ante cortes inesperados.
  • Sintaxis SQL Estándar: Facilita migrar hacia motores de alta concurrencia si la escala del proyecto lo exige en el futuro.

Especificación de Endpoints REST

Método Ruta / Endpoint Cuerpo / Parámetros Respuesta Exitosa Descripción
POST /registro {"usuario": "...", "contraseña": "..."} 201 Created Crea el usuario y guarda el hash en SQLite.
POST /login {"usuario": "...", "contraseña": "..."} 200 OK Verifica hash y abre la sesión del usuario.
GET /tareas Accept: text/html | app/json 200 OK HTML de bienvenida o listado JSON.
POST /tareas {"titulo": "...", "descripcion": "..."} 201 Created Crea una tarea vinculada al usuario logueado.
PUT /tareas/<id> {"completada": true} 200 OK Cambia el estado de una tarea.
DELETE /tareas/<id> Ninguno (ID en ruta) 200 OK Elimina la tarea especificada.
